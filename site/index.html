Overview

Prototype

An evidence-centered research workbench that makes provenance inspectable, not opaque.

What it is

bioscientist-os ingests small biomedical paper corpora, normalizes them, searches and clusters them, extracts structured claims from abstracts using transparent (non-LLM) baselines, links those claims to biological entities and database records, and assembles evidence tables in which every cell carries explicit provenance.

The key artifact is not a summary. It is an auditable chain:

paper → extracted claim → biological entities → database links → support / conflict / uncertainty → visual report

The methodological question

How can a biomedical research assistant make evidence provenance explicit enough that scientists can inspect claims, supporting papers, database links, conflicts, and uncertainty — rather than receiving opaque summaries?

Every output separates four epistemic levels and never collapses them: observed metadata, extracted claim, inferred relation, and unsupported hypothesis.

Constraints

  • CPU-only by default (target: AWS m5.2xlarge-class); no GPU.
  • No paid APIs in the default path; connectors are fixture/cache-backed.
  • Tests run fully offline from small committed fixtures.
  • No large datasets, model weights, secrets, or caches are committed.
  • Any LLM integration is optional, off by default, mock-backed, cost-guarded.

Status

The project contract (plan, docs, website, permission policy, and an autonomous milestone runner) exists, and Milestones 0–11 have landed — only the final cleanup / quality-gate pass (M12) remains. The repository is an importable package with a runnable biosci CLI, the typed data model (pydantic schemas with provenance) plus small, clearly-labeled fixtures exist, those fixtures ingest into a deterministic local SQLite database, the corpus is searchable (BM25F, with a per-term score explanation) and groupable into topics, a transparent, non-LLM baseline recognizes entities and extracts claims from the abstracts, the workbench assembles evidence tables grouped by a research question — every cell with provenance, database links, and a heuristic support/conflict/unknown signal (see Evidence tables) — and an offline-first database-connector layer serves records by id with an explicit data_source provenance (fixture / cache / live), and the workbench generates five figures (timeline, topic clusters, evidence matrix, link graph, support-vs-conflict) — data always, PNGs when the optional matplotlib extra is installed, and a gold-label self-evaluation scores the pipeline (ingestion, search recall, entity precision/recall, claim sanity, evidence completeness, provenance coverage) with explicit denominators and Wilson intervals, and the workbench assembles an end-to-end research memo per question — key papers, the evidence table, database links, conflicts/uncertainties, and suggested next experiments emitted only as explicitly unsupported hypotheses, with no medical advice. An optional, cost-guarded LLM adapter (mock / cache / opt-in Anthropic) is available but kept off the default path — the pipeline and tests use no language model. See the Milestones page for live status and Results for measured numbers.

What it does not claim

  • Not a medical-advice, diagnostic, treatment, or clinical-decision tool; no drug efficacy/safety/dosing — output that reads as clinical advice is a defect (safety).
  • Not expert-curation quality: dictionary entity recognition misses synonyms and novel entities; rule/template claim extraction has limited recall and is brittle to paraphrase and negation.
  • "Support / conflict / unknown" is a heuristic textual signal, not an adjudication of biological correctness or study quality.
  • The numbers above are not a benchmark or a state-of-the-art claim; they certify the pipeline behaves as specified on a small fixture set.
  • The optional LLM adapter adds no measured pipeline capability and never speaks as a transparent baseline.
