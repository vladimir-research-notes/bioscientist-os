Search & topics

Done (M3)

A transparent, CPU-only lexical search whose score is its own explanation, plus simple topic grouping.

Brief

Search ranks the ingested papers with BM25F, the multi-field variant of Okapi BM25, over three weighted fields — title (×3.0), keywords (×2.0), and abstract (×1.0). Every hit carries a per-term, per-field breakdown: the inverse document frequency of each query term, which fields it matched in, and its additive contribution to the score — so the total score is exactly the sum of its parts and nothing is opaque.

biosci search "cellular senescence inflammation" --db results/raw/bioscientist.db
biosci search "IL-6 SASP senescence" --db results/raw/bioscientist.db --explain
biosci topics --db results/raw/bioscientist.db --threshold 0.15

Topic grouping is single-link clustering at a cosine threshold — the connected components of a TF-IDF cosine-similarity graph — with each group labeled by its most distinctive terms. Results are rankings and groupings of observed-metadata papers: search and topics make no claims and assert no biology.

Deeper

The tokenizer is deliberately simple and documented: text is lower-cased and split into alphanumeric tokens that keep internal hyphens, so biomedical surface forms such as IL-6, p16INK4a, and ATG7-dependent survive as single tokens. There is no stemming and no synonym or identifier expansion — those would hide which literal term matched. A direct consequence: IL-6 and IL6 are different tokens, and search does not unify them (mapping surface forms to canonical gene/protein identifiers is entity linking, Milestone 4).

BM25F uses k1 = 1.5 and b = 0.75; idf is the non-negative Robertson form. Hits sort by descending score then by paper_id (a stable tie-break), so a query reproduces exactly on every build. An optional --method tfidf mode scores papers by smoothed, L2-normalized TF-IDF cosine to the query — the same vectors used for topic grouping.

Single-link clustering is transparent but has honest limits: it can chain loosely-related papers through intermediate links, and it cannot place one paper in two themes (a paper about autophagy and the SASP lands in only one group). The number of groups is monotone in the threshold — raising it only removes edges, so groups never merge. The threshold (0.15 by default) was chosen on these fixtures and is reported in every result, not hidden. The labels describe a group; they are not asserted topics of the field.

The index is recomputed in memory from the database on each run rather than persisted. For the small corpora this workbench targets that is a pure, deterministic function of the database with negligible cost; it would be a scaling limitation on a large corpus, which is stated rather than hidden.

ImplementationDone (M3): SearchIndex (BM25F + TF-IDF cosine) in search/index.py, single-link topic grouping in search/topics.py, the transparent tokenizer in search/tokenize.py, and result dataclasses in search/model.py, wired to biosci search / biosci topics.
Tests / results28 new tests (95 total, offline). On 18 indexed papers (436-term vocabulary): topic grouping at threshold 0.15 yields 10 groups (4 multi-paper, 6 singletons); on 8 single-target labeled queries the expected paper is rank 1 in 7/8 and in the top 3 in 8/8 (a sanity check on a tiny synthetic corpus, not a recall benchmark — see Results and Evaluation).
Open questionsWhether to add identifier-aware matching (IL-6 ↔ IL6) to search now that dictionary entity recognition exists (M4, done); whether single-link clustering should be replaced by an overlapping/soft topic method; whether a persisted index is ever needed at this scale.
