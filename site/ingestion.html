Ingestion

Done (M2)

Load small fixtures into a deterministic local SQLite database.

Brief

Fixture ingestion loads the committed corpus through the typed schemas (validating every record) and writes one row per object into SQLite, keeping each record's data_source and synthetic provenance as first-class columns. Re-ingest is idempotent (UPSERT by stable id — no duplicate rows), and the database is content-deterministic: a SHA-256 content digest over all rows is identical across separate builds from the same fixtures.

biosci ingest data/fixtures --db results/raw/bioscientist.db
biosci stats   --db results/raw/bioscientist.db

Ingested rows are observed metadata only — directly read from a source record. No claims, relations, or hypotheses are produced at ingestion time (those are later milestones).

Deeper

Three tables hold the corpus: papers (one row per Paper, with authors/keywords/external-ids stored as canonical sorted-key JSON so a row round-trips back into the exact pydantic model), database_records (UniProt-style proteins and Open Targets-style associations, keyed by (source, record_id)), and research_questions. A small ingest_meta table records the schema and package version. No timestamps or run ids are written, which is what makes the content digest stable; the digest itself sorts rows by primary key, so it is independent of insertion order and on-disk page layout. (Raw file bytes can still vary across libsqlite versions; the digest is the robust determinism guarantee.) Validation runs before any file is created, so a malformed corpus aborts with no partial database.
