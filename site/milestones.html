Milestones

Scaffold

Live build status. Each milestone is one autonomous Claude run that commits locally.

How the build runs

The human launches scripts/run_all_milestones_with_claude.sh. Each milestone is a single claude -p invocation under a strict permission policy (no push, no network fetch, no secret reads) that implements one milestone, updates this site, and commits locally. The runner stops on any failure, dirty tree, or missing commit.

Milestone 9 — delivered

The workbench now produces its narrative capstone: a structured research memo per research question, assembled from the pipeline without any new, unaudited computation. Delivered: src/bioscientist_os/evidence/memo.py — the MemoReport (Markdown + deterministic JSON views), build_memo_report / load_memo, BM25F key-paper ranking with an honest retrieval recall gap, a candidate cross-paper directional-disagreement detector, and a mechanical unsupported-hypothesis generator — plus the biosci memo CLI command (--question, --question-id, --out, --json, --min-confidence, --limit, --max-papers, --max-hypotheses) and scripts/07_generate_memo.py. The memo has nine sections, each tagged with its epistemic level so the four levels are never collapsed; suggested next experiments are emitted only as explicitly unsupported, UNTESTED hypotheses framed as research questions. Its counts and links reconcile exactly with the M5 evidence table. On the three fixture questions: 31 / 29 / 8 evidence rows at 100% provenance coverage; the designed autophagy↔senescence disagreement (papers 006 vs 007) surfaces as a candidate directional disagreement.

Validation: python3 -m pytest -q → 243 passed, 1 skipped (offline); ruff check clean on the new files. A memo is a research-assistance artifact, not medical, diagnostic, or treatment advice; the support label is a heuristic textual signal, database links are inferred relations, and the suggested experiments are unsupported hypotheses for a human to evaluate — never recommendations (safety).

Milestone 8 — delivered

The workbench now evaluates its own pipeline against committed gold labels — not biological truth. Delivered: a new evals package — metrics.py (a Proportion that carries its denominator plus a 95% Wilson interval, with the critical value from the stdlib statistics.NormalDist), gold.py (typed loaders for the committed labels under data/fixtures/gold/), and harness.py (six evaluators, the EvalReport container, and the database-backed run_eval(db)) — plus the gold labels themselves (6 queries / 16 relevant pairs; 6 abstracts / 24 gold entities), the biosci eval CLI command, and scripts/06_run_eval.py. It scores ingestion correctness (40/40), BM25F search recall (recall@3 = 14/16, recall@5 = 16/16), entity precision/recall (1.000 / 0.917, F1 0.957), claim sanity (42/42), evidence completeness (68/68), and provenance coverage (68/68), each with its denominator and Wilson interval. The report is deterministic (byte-identical eval_report.json across runs).

Validation: python3 -m pytest -q → 223 passed, 1 skipped (offline); ruff check clean on the new files. This evaluates the pipeline on a tiny, partly-synthetic corpus — N is small by construction, so intervals are wide (even 40/40 has a 95% lower bound of 0.912) and the rule-based recall misses are surfaced, not hidden (IL-8 is unmodeled; p16INK4a-expressing mis-tokenizes). Passing it means the pipeline behaves as specified, not that its extractions are biologically authoritative (safety).

Milestone 7 — delivered

The workbench now produces five figures over its own reports, each split into inspectable data and optional rendering. Delivered: src/bioscientist_os/visualization/model.py (frozen, matplotlib-free, provenance-carrying figure-data dataclasses), visualization/build.py (builders that re-present the M3 topic grouping, M4 extraction, and M5 evidence tables, plus load_visualizations(db)), visualization/figures.py (an optional matplotlib renderer whose write_visualizations always writes the data JSON and renders PNGs only when the viz extra is installed), the biosci figures CLI command, and scripts/05_generate_visualizations.py. The figures are a literature timeline (18 papers / 17 years), a topic-cluster summary (10 groups, 6 singleton), a claim/evidence matrix (papers × question entities, support/conflict/unknown), an entity/database-link graph (53 nodes, 80 edges), and a support-vs-conflict table (3 questions: 36 support / 13 conflict / 19 unknown). The figure data is deterministic (byte-identical visualizations.json across runs).

Validation: python3 -m pytest -q → 195 passed, 1 skipped (offline); ruff check clean on the new files. The figure-rendering test is skipped when matplotlib is absent, so the core path stays light. The matrix/table support signal is a heuristic textual signal and the link-graph database edges are inferred relations — neither is a biological or clinical verdict (safety). Figures summarize a tiny, partly-synthetic corpus; they are descriptive, not field maps.

Milestone 6 — delivered

The workbench now has an offline-first database-connector layer: a clean adapter that hides where a record comes from behind one interface and keeps an honest data_source provenance on every record. Delivered: BaseConnector plus the connector error hierarchy and a deterministic, injectable-sleep retry helper (databases/base.py); the required FixtureConnector with uniprot / opentargets / papers factories (databases/fixture.py); a gitignored read-through CachedConnector under data/cache/ (databases/cache.py); an opt-in, off-by-default LiveConnector with an injected transport and one best-effort UniProt example (databases/live.py); a ConnectorRegistry with load_connectors / open_connectors (databases/registry.py); and the biosci db CLI (sources, list, lookup, with --cache and --json). Provenance is stamped, never passed through: a fixture lookup reports fixture, a cache hit reports cache (and serves offline with no inner call), a live fetch reports live. The three fixture connectors serve 10 / 9 / 18 records.

Validation: python3 -m pytest -q → 178 passed (offline); ruff check clean on the new files. The connector layer serves observed metadata only — no claim, relation, or biological assertion. Live connectors are opt-in and never run in CI; only the fixture/cache path carries reproducibility guarantees (database connectors).

Milestone 5 — delivered

The workbench now assembles its headline artifact: an evidence table grouped by a research question. Delivered: src/bioscientist_os/evidence/table.py — question resolution (match a stored fixture question by text/id, or synthesize one from free text; recognize its entities with the same dictionary), a relevance filter (keep claims that mention ≥ 1 question entity), a transparent support/conflict/unknown cue heuristic (rule:support-cues), database-link assembly (UniProt/HGNC xrefs + Open Targets-style associations), and the EvidenceReport container with CSV/JSON views; the biosci evidence CLI command (--question, --question-id, --out, --min-confidence, --limit, --json); and a scripts/04_build_evidence_table.py wrapper that writes one CSV per question plus a combined JSON. Every row carries full per-cell provenance and keeps the four epistemic levels separate (snippet = extracted claim, entity names = observed metadata, database links = inferred relation, support label = heuristic textual signal). On the three fixture questions the builder produces 31 / 29 / 8 rows at 100% provenance coverage; the senescence–inflammation table is 17 support / 6 conflict / 8 unknown.

Validation: python3 -m pytest -q → 143 passed (offline); ruff check clean on the new files. The support/conflict/unknown label is a heuristic textual signal, never a biological or clinical verdict (safety). It reads one sentence's phrasing and does not detect cross-paper directional conflict — a documented limitation. Counts describe builder behavior, not quality (evaluation is M8).

Milestone 4 — delivered

The corpus now yields recognized entities and extracted claims through a transparent, non-LLM baseline. Delivered: a fixture-built EntityDictionary (src/bioscientist_os/evidence/dictionary.py) with longest-match recognition, built from the UniProt protein records (real accession/HGNC db_xrefs) plus Open Targets surface synonyms and a short, explicit curated process/phenotype seed; a span-exact tokenizer and sentence splitter (evidence/text.py); the rule-based extractors (evidence/extract.py) producing BiomedicalEntity (level observed metadata, dict:exact) and Claim (level extracted claim) objects with optional proximity subject–relation–object triples (rule:svo / rule:assoc); the biosci extract CLI command (with --paper, --min-confidence, --json); and a scripts/03_extract_claims.py wrapper that writes results/processed/claims.{json,csv} and entities.csv. Over the 18 abstracts: 26 dictionary entities / 61 surfaces → 63 entity mentions, 42 claims, and 15 relation triples; all 105 spans round-trip against the source abstract. The designed conflict pair surfaces (autophagy promotes vs restrains senescence) — material for the Milestone 5 support/conflict logic.

Validation: python3 -m pytest -q → 119 passed (offline); ruff check clean on the new files. Entities are observed metadata (recognized mentions); claims are extracted claims read from abstracts; a triple is part of the claim, not an inferred relation. Counts describe extraction behavior, not quality — precision/recall against gold labels is M8. No support/conflict or biological assertion is made here.

Milestone 3 — delivered

The ingested corpus is now searchable and groupable, on CPU and offline. Delivered: a field-aware in-memory SearchIndex (src/bioscientist_os/search/index.py) with a transparent BM25F scorer over weighted title / keywords / abstract fields and an optional TF-IDF cosine mode; single-link cosine topic grouping (search/topics.py); the transparent tokenizer (search/tokenize.py); the biosci search and biosci topics CLI commands (with --explain and --json); and a thin scripts/02_build_index.py wrapper. Every search hit reports a per-term, per-field breakdown whose contributions sum exactly to the score; every topic group reports its distinctive label terms. Indexing the 18 papers gives a 436-term vocabulary; topic grouping at threshold 0.15 yields 10 groups (4 multi-paper, 6 singletons), and on 8 single-target labeled queries the expected paper is rank 1 in 7/8 and in the top 3 in 8/8.

Validation: python3 -m pytest -q → 95 passed (offline); ruff check clean on the new files. Results are rankings and groupings of observed-metadata papers; search and topics produce no claims. The labeled-query numbers are a sanity check on a tiny synthetic corpus, not a recall benchmark (the rigorous evaluation is M8).

Milestone 2 — delivered

The fixture corpus now ingests into a local SQLite database through a dedicated storage layer. Delivered: SQLiteStore (src/bioscientist_os/storage/sqlite_store.py) — a stdlib sqlite3 backend with idempotent UPSERT writes, exact round-trip back into the typed schemas, and a content-deterministic SHA-256 digest; the ingest_fixtures() pipeline (src/bioscientist_os/ingest/pipeline.py) that validates every record before touching disk and reports what it wrote; the biosci ingest and biosci stats CLI commands; and a thin scripts/01_ingest_fixtures.py wrapper. Ingesting data/fixtures/ yields 18 papers, 10 UniProt-style protein records, 9 Open Targets-style associations, and 3 research questions (40 rows). Re-ingest is idempotent (0 inserted, 40 updated) and two separate builds produce the identical digest.

Validation: python3 -m pytest -q → 67 passed (offline); ruff check clean on the new files. Ingested rows are observed metadata only (data_source=fixture); no claims or relations are produced yet. The generated .db lives under results/ (gitignored, reproducible from fixtures).

Milestone 1 — delivered

The data model exists as typed pydantic v2 schemas with provenance as a first-class field. Delivered: nine core schemas (Paper, Author, BiomedicalEntity, Claim, EvidenceItem, DatabaseRecord, EvidenceTable, ResearchQuestion, WorkbenchRun) plus a shared Provenance submodel and four controlled vocabularies (DataSource, EpistemicLevel, EntityType, SupportLabel) in src/bioscientist_os/schemas.py; a thin fixture loader (src/bioscientist_os/fixtures.py) that parses and validates the committed corpus and stamps data_source = fixture; and small, clearly-labeled fixtures on the cellular-senescence / longevity / autophagy theme — 18 papers (synthetic), 10 UniProt-style protein records (modeled on real accessions), 9 Open Targets-style association records (synthetic scores), and 3 research questions.

Validation: python3 -m pytest -q → 50 passed (offline); ruff check clean on the new files. The loader does parse + validate only — database ingestion and normalization are Milestone 2, so no .db file is produced yet.

Milestone 0 — delivered

The repository is now an importable, testable Python package with a runnable CLI. Delivered: src/bioscientist_os/ (package metadata, the four epistemic levels, and the non-clinical safety note as importable constants); the biosci CLI (typer) with version, info, and env-check subcommands; seven empty-but-importable subpackages (ingest, search, evidence, databases, visualization, storage, evals); and a shared environment-check module that both biosci env-check and scripts/00_check_environment.py call.

Validation: python3 -m pytest -q → 20 passed (offline); python3 -m bioscientist_os --help and biosci --help work. No functional ingestion/search/extraction yet — the subpackages are skeletons.
