Database connectors

Done

Offline-first adapters with an explicit data_source provenance on every record.

Brief

A base connector interface with a required fixture-backed connector, a local read-through cache, transient-error retry/backoff, and an explicit data_source provenance field (fixture / cache / live) on every record. A connector hides where a record comes from behind one small interface (fetch(id), get, fetch_many, ids), so a memo or evidence table can show whether a database link is committed, cached, or freshly fetched. Live API connectors are optional, off by default, and never a test dependency.

BaseConnector
  ├─ FixtureConnector   committed records   → data_source=fixture   [required]
  ├─ CachedConnector    read-through cache   → data_source=cache     (data/cache/, gitignored)
  └─ LiveConnector      opt-in HTTP          → data_source=live      [opt-in, off by default]

Cache and provenance

The cache layer (CachedConnector) wraps any connector and persists each fetched record as canonical JSON under data/cache/<source>/<id>.json (gitignored). Its provenance discipline is the point: a cache hit is stamped data_source=cache (the bytes came from the local file) and needs no inner connector at all; a cache miss returns the inner connector's own data_source and writes a cache-stamped copy for next time. So the first lookup reports where the data really came from, and the second reports cache — never the reverse. A cache warmed from a source still serves offline with the inner connector gone.

Retry and the opt-in live path

call_with_retries retries only transient failures (timeouts, 5xx, 429) with bounded exponential backoff, wraps an exhausted budget in a ConnectorError, and never retries a permanent error; the sleep is injectable so the schedule is deterministic and tests run instantly. A missing id is None (fetch) or RecordNotFound (get), distinct from an operational failure.

LiveConnector is off by default: with allow_network=False it raises before any transport call, so constructing one is inert. Its HTTP transport is injected, so the parse/retry/provenance logic is exercised entirely offline with a mock transport in tests; the real stdlib transport is reached only when a caller opts in. One example ships (uniprot_live_connector) to show the shape of a real adapter — best-effort, never run in CI.
